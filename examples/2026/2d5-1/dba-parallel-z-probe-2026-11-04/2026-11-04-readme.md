## Why the flag is insufficient

`SpaceChargeConfigBuilder.cpp:308` rejects multiple MPI ranks, and `SpaceChargeConfig.cpp:126` rejects parallel grid dimensions for FFT2D5. The solver also has a runtime rank check. Beyond those checks, `FFT2D5FieldStorage.cpp` constructs a serial 3D field layout and a shared 2D workspace. The slice loop uses global slice indices. These are implementation limitations, not guards that can safely be disabled.

Correct MPI partitioning along reference-path s would require field-slab ownership, routing particle deposition and field gathering to the owning slab, local/global slice indices, periodic rank-boundary halo exchange, and suitable communicators for independent local transverse solves. Validation must compare total charge, fields by particle ID and tracking endpoints against one rank, including particles near rank boundaries and the closed-ring seam.

`PARFFTZ` requests MPI grid decomposition; it does not schedule OpenMP slice tasks. OpenMP already parallelizes the particle kernels in the measured build. Concurrent slice FFT execution needs a batched implementation or appropriately independent workspaces and thread-safe backend execution. The current shared workspace cannot simply be used concurrently.
