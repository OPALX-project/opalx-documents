# FFT2D5 profiling of the DBA pilot

Steady-state time is split almost equally between **reference-path projection (46%)** and **slice Poisson/FFT work (47%)**. The current build uses the **heFFTe stock CPU FFT backend**. These are two distinct optimization targets.

## Measurements

Two separate 100-step pilots used the exact previous feasibility input: 100,000 matched KV particles, full DBA ring, 5.602212 nC, 64×64×512, 3 ps, four OpenMP threads, one MPI rank, ORIGINAL transverse FFT2D5 with longitudinal force disabled. The macOS stack sample covered 20 seconds at 1 ms requested intervals and yielded 16,467 main-thread samples. Recursive frames were counted once per sampled stack using non-overlapping leaves. Worker and MPI-progress threads are excluded from these wall-time estimates. Across the three OpenMP worker threads, projection accounts for 46.4% of samples and runtime/waiting/unclassified work for 52.9%; no stock FFT calculations appear on those workers. The serial slice loop and CPU stock transforms therefore leave substantial worker capacity unused during the transform phase.

## Where the work occurs

1. `src/SpaceCharge/FFT2D5/FFT2D5Algorithm.hpp:384`, `convertToFrenetSerret`: for each particle, the loop at line 396 searches all 2,606 reference segments. A second loop at line 421 sums preceding segment lengths to recover s. The same conversion is performed for both deposition and gather. This is approximately **521 million nearest-segment checks per step**, plus repeated arc-length sums. Sampling locates the time in this function but does not separate its two internal loops. Actual deposition/gather work outside projection is only about 0.4% of the sampled main-thread time.
2. `FFT2D5Algorithm.hpp:564`: 512 occupied slices are processed sequentially through a reused 2D workspace. Each step performs 512 independent 2D Poisson solves. The measured coupling/copy kernels each execute 51,200 times in 100 steps. Green-function generation occurs once, consistent with workspace/plan reuse.
3. `FFT2D5Poisson.cpp:123` calls the forward/backward transforms. Runtime stacks identify `heffte::stock_fft_executor_r2c`, `plan_stock_fft` and `pow2_FFT_helper`. CMake and generated configuration show FFTW and MKL disabled. Each 64×64 open-boundary slice uses a doubled transverse grid. IPPL's FFT packing/unpacking alone costs about 9% of total measured wall time, with roughly 4,096 small packing kernels per step.

## Optimization priorities

- Precompute segment vectors, inverse squared lengths and cumulative arc lengths; reuse each particle's projection between deposition and gather within the same field solve, where particle positions do not change.
- Replace the exhaustive nearest-segment search with an exact accelerated lookup. A spatial index or previous-segment candidate needs a reliable global fallback, preserving nearest-segment selection and periodic seam behavior.
- Benchmark an optimized CPU FFT backend and reduce repeated packing/launch overhead by batching the independent 2D slices. This has not been implemented or timed.

These changes can preserve the existing field model and timestep. Removing projection completely would still provide at most about 1.9× overall speedup at the measured split; it alone cannot turn the estimated 54-day run into an overnight job. The 3 ps, 16-turn configuration entails about **3.2 billion 2D slice solves**. Any reduction in solve frequency or change in boundary stepping needs its own convergence validation.

## Validation and scope

Both profiled runs completed 100 steps, retained all 100,000 IDs and the correct charge, and produced finite arrays at t=300 ps. Relative to the unprofiled baseline, the maximum laboratory endpoint differences are below 3.6e-13 m in position and 1.2e-12 in beta-gamma momentum. Inputs, native initial checkpoint and executable hashes match the feasibility pilot. No OPALX source, build configuration, executable, physics tolerance or field-update schedule changed. Only a read-only profiling plugin was compiled under `build-omp/profiling/fft2d5`.
