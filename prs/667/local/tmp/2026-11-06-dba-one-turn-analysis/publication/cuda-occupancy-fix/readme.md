# CUDA occupancy-kernel launch fix

The FFT2D5 algorithm tests crashed at a null host program counter while launching the slice-occupancy kernel in solvePoissons<NullDiagnostic>. GDB and disassembly identify the indirect call through the NVCC extended-lambda fp_copier helper. The templated header kernel is instantiated in both the solver library and the test translation unit. The kernel had not reached device execution when the crash occurred.

The remaining extended lambda in FFT2D5Algorithm.hpp is replaced by OccupiedSlicesFunctor, following the named-kernel pattern already used in the same header. It retains the same array access, zero comparison, loop order, early exit and atomic marking. There is no numerical-method, tolerance, field-model or IPPL change.
