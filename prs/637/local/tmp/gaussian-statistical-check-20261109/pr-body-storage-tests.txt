PROBE currently parses in cyclotron lattices but produces no crossing output. This implements passive cyclotron segment diagnostics and supports collecting turn profiles during coasting and accelerating space-charge runs.

Refs #615. This PR covers cyclotron-sector and native RING/FFA particle tracking, with native laboratory probe output and a general coordinate-frame adapter.

## Changes

- Observe accepted particle endpoints across finite segments in the laboratory X–Z plane, in both directions. Diagnostic histories follow particle IDs through compaction and MPI migration without changing particle states, fields, reference motion or step scheduling.
- Write HDF5/ASCII crossing records. Cyclotron output additionally provides cumulative radial `.hist` / per-reference-turn `.peaks` summaries; FFA output contains phase-space records only because its ring centre may be translated. Flush every 100 accepted steps, at completion and before reporting a collective SINGLEGAP transport failure. Keep fresh-output checks and reject unsupported restart/continuation.
- Select coasting cyclotron sectors conservatively from current bunch bounds, preserving native field support checks. This fixes the periodic path-index omission that caused the approximately 23 m particle/reference separation in the ten-turn test.
- Extend SINGLEGAP tracking to one unpolarized positive-proton bunch with PIC self fields. MIDPOINT uses a ballistic predictor and frozen-field Boris half kicks around external transport; PRESTEP remains available. Localize the reference stopping duration before prediction/gather and preserve complete RF kicks and the established single-particle endpoint convention.
- Share mapped field kernels, include all three momentum components in RF energy balance, and report field-support/RF-kick failures with particle ID, time and laboratory state.
- Consolidate selection/descriptors in `DeviceExternalField` and RF event ordering/localization in `TrackReferenceStep`; PIC orchestration stays in `ParallelTracker`. Add host/device unit coverage and reproducible probe/bunch integration scripts.

## Limits and follow-up

A100 shared-Release native probe tests and small one-/two-GPU FFA comparisons have passed; these are correctness checks rather than production-scale PIC benchmarks. The collective split is a thin-gap approximation and this coarse run is not a mesh/timestep convergence study. It transports one bunch without neighbouring-turn/bunch space charge or a septum model; vertical RF focusing is not included. Restart/continuation and larger probe performance optimizations remain deferred.

The earlier 16³ run's failure near 584 MeV cannot be reconstructed from its missing buffered state. Periodic flushing and classified failure diagnostics improve future diagnosis; the successful 580 MeV run does not claim to resolve that failure.

User/physics manual edits are prepared in the separate manual checkout and are outside this source-repository PR.

## Failure storage and unit-test stability

Commit `648ce4ea5` adds the reviewed tracker cleanup and fixes the remaining unit-test failures.

- Replace the per-particle, per-step RF diagnostic array with one persistent failure record per MPI rank. Only failing particles attempt an atomic claim; the successful claimant writes a coherent particle ID and diagnostic payload. The host reads the record after kernel completion. Storage is constant per rank instead of proportional to the local particle count. Selection is the first device claimant rather than the lowest local particle index.
- Share the cyclotron field-support predicate between scalar and device evaluation, including consistent rejection of nonfinite positions. Consolidate common RF validation and immutable lattice preparation while keeping the device kernel in the existing public integration method for NVCC.
- Fix parallel test interference: the single-rank and MPI loss-data fixtures could delete each other's HDF5 files, and the static/dynamic FM2D fixtures shared a temporary directory. Give generated maps, checkpoints, diagnostics, reference paths and spectrum CSVs owned directories. A shared native C++ helper atomically claims directories, broadcasts shared paths and creation errors within MPI jobs, and leaves cleanup to the owning rank after writers close and peers synchronize. Remove deletions of files the fixture never created. CMake/CTest parallel scheduling remains unchanged; no external scripts or data dependencies are added to native unit tests.
- Replace the Gaussian test's invalid fixed `5.5σ` maximum with Bernstein exceedance-count checks and a sample-size-dependent normal maximum. Split an explicit `10⁻⁶` false-alarm budget between the new tail-check families; the existing RMS checks retain their own thresholds. Keep the sampler, seed, 100,000-particle sample and strict longitudinal cutoff unchanged, and check all six components for finiteness.

Validation of the published fixes:

- **137/137 CTest targets pass** locally with OpenMP and on Linux Debug/OpenMP.
- All 29 output-isolation targets pass; 20 concurrent FM2D pairs pass, and five explicit two-/four-rank checks pass with 18 native case executions and zero skips.
- Gaussian coverage passes on one/two ranks with one/four threads: 48 native case executions, zero skips. All seven distribution targets pass.
- Focused A100 tracker/RF/probe coverage passes 111 case executions. Four CPU bunch comparisons are byte-identical before/after the tracker cleanup, and actual GPU tracker success/failure checks pass on one/two ranks. This A100 coverage applies to the tracker subset; it is not a fresh CUDA validation of every subsequently isolated fixture. GPU tracker integrations use `TYPE=NONE` and zero charge; charged PIC comparisons run on CPU.

Larger probe synchronization, history-storage and summary-output optimizations remain deferred to #674.
